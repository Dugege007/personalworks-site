## 1. 背景与目标

用户要求（2026-10-19）：给个人网站「心得」文章增加标签功能；功能体验对齐「摄影」栏目的标签，但**两个栏目的标签库必须分开、不可混用**。资源编辑工具与网页都要完善。先写完整落地方案，评估后再开始实现。

摄影侧已经具备：内容层类型键（`themes`）与自由标签（`tags`）、本机分栏预设词库、检视栏／标签窗芯片与下拉、网页多维筛选（类型、自定义标签、年份、地点、「无标签」）以及统一资源定位符查询参数。心得侧索引里虽已有 `body.tags` 与配图 `images[].tags` 字段形状，且 `NoteCommands` 已能写入标签，但前端未暴露、未展示、未筛选；资源编辑工具的 `CanTag`／`RefreshResourceTags` 仍只绑摄影事实栏目，心得打不开同一套标签窗；若直接复用 `TagEditorCatalog.BuildSuggestions(..., includeTypes: true)`，会把摄影类型键与默认词「展馆」「随拍」灌进心得建议列表，造成混库。

本计划把「对齐体验、硬性分库」落成可实现的数据约定、规范化规则、编辑工具改动、网页筛选与分阶段验收标准，并列出需用户拍板的开放问题与推荐选项。

| 术语 | 含义 |
|------|------|

| **标签库／词库／预设** | 本机文件 `%AppData%/SiteMediaStudio/tag-vocab.json` 中，按「工作区根＋栏目 channel key」分栏存放的自由标签预设列表。**不进 Git**，不代替内容层。 |

| **「无标签」** | 筛选语义标识（摄影侧为 `untagged`／文案「无标签」），**不是**可写入内容层的自由标签字面。 |
| **多选交集** | 同一筛选维内选中多个取值时，资源必须**同时**命中全部取值才保留（摄影 `photoFacet.ts` 的 `matchesEvery`）。 |

## 3. 现状与缺口

### 3.1 摄影（参考实现，本期不改产品语义）

- **内容层**：作品／帧上有冻结类型键 `themes` 与自由 `tags`。
- **编辑工具**：`TagEditor`／`TagWindow`／`TagEditorHost`／`TagEditorCatalog`；`TagVocabStore` 读写 `%AppData%/SiteMediaStudio/tag-vocab.json`，按工作区根＋栏目 channel key 分栏存自由标签预设。
- **`PhotoFactRules`**：类型键（风光／人文／人像／游戏／人工智能摄影等冻结表）、默认自由标签「展馆」「随拍」、规范化（拒绝四位年份、拒绝类型键、拒绝「无标签」字面）。
- **网页**：`PhotoCatalogPage`（及拍摄页同类逻辑）＋`photoFacet.ts`：类型第一行、自定义标签第二行、年份／地点、统一资源定位符查询参数筛选；同维多选为**交集**。
- **`ShellViewModel.CanTag`／`RefreshResourceTags`**：当前绑定摄影（`PhotoFactRules.RequiresFacts`／`SelectedPhotoCardList`），心得栏目打不开同一套标签窗。

### 3.2 心得（缺口）

| 缺口 | 说明 |
|------|------|
| 前端未暴露标签 | 索引 `index.json` 条目已有 `body.tags: string[]` 与 `images[].tags`；仓库当前可见样例可能是空数组，字段形状已就绪。前端 `NoteCard`／`listNotes`／`toCard` **未**带上 tags；`NotesPage`／`NoteDetailPage` **无**标签展示与筛选。 |
| 类型字段名不一致 | 发布索引 JSON 使用属性名 `body`；TypeScript 侧 `NoteRecord` 写成 `bodyMeta?: NoteResource`。一期实现必须对齐读取路径（推荐前端按发布 JSON 的 `body` 读取，或在选择层做显式映射），避免「索引有 tags、页面永远读不到」。 |
| 写入已有、入口未开 | `NoteCommands` 已支持 `TagsUpdate`：可写 `entry.Body.Tags` 或配图 `image.Tags`。`NoteRules.ChannelKey = "notes"`。但检视栏／标签命令未对心得启用。 |
| 混库风险 | `TagVocabStore` 结构上可按 channel 分库；`TagEditorCatalog.BuildSuggestions(..., includeTypes: true)` 会灌入摄影 `PrimaryFacetList`（含类型键与「展馆」「随拍」）。心得路径若直接 `includeTypes: true` 即混库。 |
| 配置文件无 tags | `心得.json`（`NoteConfig`）当前无 tags 字段。权威访客标签在**上页后的 index.json**（与摄影一致：内容层／索引为发布真相）。一期不要求把标签双写进 `心得.json`，除非用户另拍板。 |

### 3.3 目标对照（评估通过后要实现什么）

1. 在资源编辑工具中，选中心得正文卡（或整篇心得目标）可编辑自由标签，体验对齐摄影的芯片／下拉／输入／删预设。
2. 本机预设与建议列表仅使用 channel key `notes`；绝不出现摄影类型键或「展馆」「随拍」等摄影默认词。
3. 网站心得列表可按自由标签筛选（统一资源定位符可分享）；详情页展示该篇标签；多选默认交集。
4. 已有索引中的非空 `tags` 原样保留，不做破坏性迁移。

## 4. 分库硬规则（写死）

下列规则为一期**必须**满足的验收红线；任一交叉出现即判失败。

1. **预设读写**：`TagVocabStore.Read`／`Remember`／`Forget` 在心得路径上**仅**使用 channel 参数 `"notes"`（工作区根仍按当前工作区）。禁止用任一摄影 channel key 读写心得预设，也禁止把心得词写入摄影 channel。
2. **建议列表**：心得构建下拉时，`includeTypes` **必须为 false**；不得并入 `PhotoFactRules.PrimaryFacetList`／`ThemeList`／`DefaultTagList`（「展馆」「随拍」）。心得若配置「默认推荐词」（见开放问题），只来自**心得自己的**常量列表（例如建议的 `NoteTagRules.DefaultTagList`），且不得与摄影默认词表混用同一静态数组。
3. **规范化拒绝摄影类型键**：心得写入自由标签时，规范化层须拒绝摄影冻结类型键字面（与摄影拒绝把类型键写进自由标签同理），并拒绝四位公历年份、拒绝「无标签」／`untagged` 字面。
4. **网页筛选项**：心得列表页的标签候选项只聚合 `notes` 索引里出现过的自由标签（外加可选的「无标签」筛选项）；**不得**从摄影作品索引或摄影词库拉取候选项。
5. **禁止拷贝**：不提供「从摄影导入标签」或「同步两端词库」的自动能力；不把摄影与心得共用同一个 channel 键。

## 5. 推荐数据模型

### 5.1 一期范围：正文级自由标签

| 层级 | 字段 | 一期角色 |
|------|------|----------|
| 发布索引 `index.json` → 每条 note 的 `body.tags` | `string[]` | **权威**：访客列表筛选与详情展示读此字段。 |
| 发布索引 → `images[].tags` | `string[]` | **二期／非目标**（默认）：字段可继续存在并由现有 `TagsUpdate` 写入，但一期产品与网页**不**以配图标签做列表筛选或详情主展示，除非用户在开放问题中要求提前做。 |
| 中转站 `心得.json`（`NoteConfig`） | 无 tags | **一期不扩展**。标签不在夹内配置文件做第二权威。 |
| Markdown frontmatter | — | **非目标**：不把标签写进 frontmatter 作为权威。 |
| 本机 `tag-vocab.json` → channel `notes` | 预设列表 | 仅加速输入与删预设；丢失不影响已发布内容。 |

### 5.2 是否引入心得「类型」冻结表

**推荐：一期只要自由标签，不引入类似摄影 `themes` 的冻结类型表。**

用户已拍板：**一期不配置默认推荐词**，只靠本机累积预设。仍**禁止**把「展馆」「随拍」或任何摄影类型键／中文类型名灌进心得建议。

### 5.3 前端投影形状

- 扩展 `NoteCard`：增加 `tags: string[]`（缺省视为空数组）。
- `listNotes`／`loadNote`／`toCard`：从索引记录的正文元数据读取 tags（实现时统一 `body.tags` 与类型定义，消除 `body`／`bodyMeta` 名不一致问题）。
- 列表筛选与详情展示只消费 `NoteCard.tags`（正文级）；不把配图 tags 并进一期筛选集合。

### 5.4 版本号

`NoteIndexFile.Version`／索引 `version` 当前为 `1`。本期仅为既有字段补齐消费路径，**不必**仅为标签展示强制升版本。若同期与主副标题／修订计划合并升版本，另按那份文档执行，不在本文件强制绑定。

## 6. 规范化与共享层

### 6.1 字面规则（与摄影自由标签对齐的部分）

对心得自由标签字面，一期采用与摄影相同的拒绝集合语义：

- 去掉首尾空白；空串忽略；同篇内去重（顺序保留首次出现，比较用序数敏感的字符串相等，与现有 `PhotoFactRules.TryNormalizeTags` 一致）。
- **拒绝**四位公历年份（1900–2100）。
- **拒绝**摄影冻结类型键（`PhotoFactRules.ThemeList` 中的 Key）。
- **拒绝**字面「无标签」与标识 `untagged`。

### 6.2 实现建议（待桌面工程师选型，二选一写进测试）

**推荐**：抽出共享的 `TagNormalize`（或同等命名的纯函数模块），接受「额外禁止的键集合」与「是否允许类型键」等参数；摄影路径继续拒绝类型键，心得路径同样拒绝摄影类型键，且**不**走 `includeTypes: true`。

**可接受的过渡**：心得路径暂时仍调用 `PhotoFactRules.TryNormalizeTags`（因其已拒绝类型键与年份），但建议列表与默认词**必须**走心得专用入口（例如新建 `NoteTagRules`：仅含 `ChannelKey` 引用、`DefaultTagList`、以及 `BuildSuggestions` 的心得包装），禁止在心得用户界面调用 `includeTypes: true`。

无论哪种，`TagVocabStore.Remember` 在写入前的规范化调用，心得 channel 不得顺带把摄影默认词表写进 `notes`。

### 6.3 与摄影默认词的隔离

`PhotoFactRules.IsDefaultTag`／`DefaultTagList` 仅服务摄影。心得默认推荐词若存在，使用独立常量（如 `NoteTagRules.DefaultTagList`），并在 `BuildSuggestions` 的心得包装里按「推荐词在前、其余按使用次数」排序，逻辑可类比摄影，但数据源分离。

## 7. 资源编辑工具改动

### 7.1 启用心得标签入口

- 扩展 `CanTag`（或并列 `CanTagNotes`）：在选中心得且目标为已入编／可写索引的正文（或约定的整篇目标）时返回真；**不要**继续用 `PhotoFactRules.RequiresFacts` 作为心得前提。
- `OpenTags`／检视栏标签区／`RefreshResourceTags`：为心得增加并行路径——读取与写入 channel 固定为 `notes`；建议列表 `includeTypes: false`；提交意图仍走现有 `TagsUpdate`，由 `NoteCommands.ApplyMeta`／`PullMeta` 写入 `entry.Body.Tags`。
- 交互对齐摄影：已选芯片、字面回车或空格提交、模糊下拉、可删预设（仅自由标签预设）、拒绝原因红字提示在「标签」标题旁，不弹窗打扰。

### 7.2 词库

- 一律 `TagVocabStore.Remember`／`Forget`／`Read(workspaceRoot, "notes")`。
- 单元测试：同一工作区下，向 `landscape-photo` 记忆「展馆」后，读取 `notes` 预设不得出现「展馆」；向 `notes` 记忆「算法」后，读取摄影 channel 不得出现「算法」。

### 7.3 本地落后 GitHub 的同步门禁

现有同步门禁文案／检查已覆盖「标签」类未发布变更时，心得标签写入应继续走同一套「改了标签须上页／发布」的门禁语义，避免本机索引已改、站点未更新却无提示。具体钩子保持与摄影／现有心得元数据一致，不另发明第二套门禁。

### 7.4 非目标（工具侧）

- 不把心得标签编辑做成必须打开摄影专用 `TagWindow` 写类型键的模式。
- 一期不做「批量给多篇心得打同一标签」的复杂编排（若检视栏多选自然能复用再做；否则列入 P2）。

## 8. 网页改动

### 8.1 数据暴露

- `NoteCard` 增加 `tags`。
- `toCard`／`listNotes`／`loadNote` 填入正文级 tags；缺字段或空数组视为无标签。
- 修正 `body` 与 `bodyMeta` 读取不一致问题（见第 3.2 节）。

### 8.2 列表页（`NotesPage`）

- 增加筛选条：**自定义标签**按全站心得中的使用次数从多到少排序（可参考 `orderPhotoCustomTags` 的思路，但数据源仅为 notes）。
- 可选：「无标签」筛选项（见开放问题；推荐一期做，与摄影一致）。
- **不**做年份／地点维（心得无对等字段），除非用户另提。
- **不**做摄影类型第一行。
- 统一资源定位符查询参数：建议使用 `tag`（可重复或多值约定与摄影一致，便于分享筛选结果）。
- 多选默认**交集**（与摄影 `matchesEvery` 对齐）。

### 8.3 详情页（`NoteDetailPage`）

- 展示该篇正文级标签芯片（无标签时不渲染空行或给出温和占位，二选一写进实现与测试；推荐无标签时不显示标签行）。
- 点击标签是否跳回列表并带上该 `tag` 查询参数：建议做（降低回流成本），列为可调项。

### 8.4 测试

- 前端：选择层与筛选纯函数单测（空 tags、单标签、多标签交集、「无标签」、查询参数往返）。

## 9. 迁移与清理

1. **索引内容**：已有 `body.tags`／`images[].tags` **原样保留**；不批量改写、不清空、不把摄影词写入心得索引。
2. **空数组**：保持合法；表示尚无自由标签。

4. **算法稿等已带标签的文章**：上页后只要索引里非空，网页 P1 完成后即应可筛可选；若当前仓库样例为空数组，不视为方案失败，以用户本机／MSI 上页结果为准。

## 10. 分阶段落地计划

**总原则**：评估确认前不动代码；确认后按 P0 → P1 → P2 推进。P0 完成后可开 P1，不必等 P2。

### P0：分库契约＋编辑工具心得标签＋测试

**范围**

- 明确心得 channel 仅用 `notes` 的读写与建议列表包装（`includeTypes: false`；独立默认推荐词若已拍板则纳入）。
- 规范化：共享或包装层拒绝年份、摄影类型键、「无标签」。
- 资源编辑工具：心得可打开标签编辑；写入走 `TagsUpdate` → `body.tags`；词库 Remember／Forget 分库。
- 修正或明确前端读取字段名的契约（可在 P0 先改选择层类型与映射，即使页面尚未做筛选条）。
- 桌面单元测试：分库互不泄漏、规范化拒绝用例、TagsUpdate 写正文标签。

**验收标准**

1. 在 YuePC（或约定桌面测试环境）上，心得可编辑正文标签并写入索引；重启工具后 `notes` 预设仍在且不含摄影默认词／类型键。
2. 自动化测试证明：摄影 channel 与 `notes` 预设互不出现对方写入的词。
3. 心得建议列表在 `includeTypes: false` 路径下不含「展馆」「随拍」与类型键。
4. 不破坏现有摄影标签用例与心得上页主路径。

**负责人**：桌面工程师主责；秘书协调测试机与验收清单。

## 11. 风险与非目标

**风险**

- 直接复用摄影 `BuildSuggestions(includeTypes: true)` 导致混库——用第 4 节红线与 P0 测试锁死。
- `body`／`bodyMeta` 名不一致导致「写了但页面没有」——P0／P1 必须先修读取契约。
- 用户以为 `心得.json` 里也能看到标签——需在工具说明或检视文案中写清「标签在上页后的索引中，以站点为准」。
- 自由标签与未来主副标题／修订计划并行改同一文件时的合并冲突——秘书协调分支与拉取请求顺序。

**非目标（本计划明确不做）**

- 不与摄影共用同一预设文件栏目键；不自动从摄影拷贝标签或词库。
- 不把标签写进 Markdown frontmatter 作为权威。
- 不改生产发布机器规则（生产发布仍仅 MSI／既有网站发布通道）。
- 一期不引入心得冻结「类型」表；不做年份／地点筛选维。
- 不把本功能扩展到其他未点名栏目（手绘等），除非另立项。
- 不在评估确认前改仓库代码或开拉取请求。
