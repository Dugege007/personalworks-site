# 一、平台总体定位与特点

## 1.1 一句话定位

**ProdLineSim_RTE（简称 PLS）是一套「三维场景编辑器 + 离散事件仿真内核 + 工艺主数据平台」三端协同的 3D 产线仿真平台**，对标 FlexSim、AnyLogic 的核心能力：工程师在 Unity 里搭三维产线、在网页里维护工艺主数据、由 Python 内核跑离散事件仿真、再把结果以「回放」形式驱回三维场景做可视化分析与诊断。

![PLS_RTE_总体架构图](/notes-assets/n-20261027-010100/arch_overall.png)

## 1.2 覆盖的产线形态

平台设计目标是覆盖多数产线仿真场景，而非单一产线：

| 形态 | 支撑能力 |
|------|----------|
| 自动化产线 / 自动化装配线 | AGV 运输、参数化传送带、多工位节拍流水 |
| 人工产线 / 人工装配线 | 工人上料、在岗门闩、工位到站动画、工时统计 |
| 混合型产线 | 同一场景内 AGV + Worker 双导航图、双角色共存 |
| 自动化仓储 / 物流 | 库位托盘、库存账本、水位预警、补料与成品入库循环 |

## 1.3 整体特点

### 特点 1：三端解耦，用数据契约缝合

平台不是单体，而是三个独立可独立运行的部分，靠两份 JSON 契约缝合：

```text
① Unity 客户端（团结引擎）           ② DataForge3D 网页（Flask）        ③ SimPy 内核（Python）
   三维场景搭建 / 回放可视化    ←契约→    工艺主数据 / 场景 JSON 导出   ←契约→   离散事件仿真编排
                                  场景 JSON 4.0.0                        场景 JSON 4.0.0
                                         │                                    │
                                         └────────── 回放 Playback JSON 4.0.0 ──────┘
                                                          ↓
                                              Unity 运行态回放 / 预警展示 / KPI 分析
```

- **场景 JSON 4.0.0**（网页 → SimPy / Unity）：工艺主数据的运输契约
- **回放 Playback JSON 4.0.0**（SimPy → Unity）：仿真结果的运输契约
- 契约 schema 版本化、带兼容性声明（导入兼容 3.2.0 及以上），旧文件不被迫升级
- 有**三层键集对齐闸门**（`kernel_catalog_alignment_check.py`）自动校验「网页 / 内核文档 / Playback 文档」三层键名一致，防契约漂移

**价值**：任一端可单独替换或升级；仿真内核不依赖 Unity 进程，可在服务器批量跑多组种子；工艺数据可脱离三维资产独立维护。

### 特点 2：仿真与表现分离

平台不追求「在三维场景里实时跑仿真」，而是**先算完、再回放**：

- SimPy 内核离线跑完整时间窗（典型 8 小时 = 28,800 秒仿真时长），产出回放文件
- Unity 侧只负责按仿真时刻驱动三维表现，支持 **x1 / x2 / x6 / x15 / x30 / x60 / x120 / x300 / x600** 九档倍速
- 支持**周期快照 + Seek**：拖动时间轴时从最近关键帧续推
- 回放可**脱离仿真独立使用**——这就是「同窗对照」（把现实数据与仿真数据放在同一时间窗对比）的基础

**价值**：倍速回放让 8 小时产线在几分钟内看完；同一份回放可反复拖拽、逐帧分析；仿真结果可存档复现。

### 特点 3：产品流向三维可视化

PLS 在三维里**用可移动的代理体把「物料在哪、走到哪」画出来**：

- 每个批次（lot）用一个 3D 代理（或指定产品模型）表示
- 代理随仿真时刻在设备挂点之间插值移动，直观呈现「在机台里加工 / 在运输途中 / 在传送带上」
- 支持**托盘载货布局**：同品走网格、混尺寸走货架 / 最大矩形装箱，在托盘上模拟货物摆放
- 支持**产品×机台外观绑定**：同一产品在不同工序可显示不同模型与颜色

### 特点 4：库存账本统计

所有库存数量都走同一套账本语义（`inventory_ledger.py` + `StorageWarningModel`）：

- 入账 / 出账 / **原子转换**（BOM 装配：扣组件、进父件、出父件走同一事务，任一前置检查失败则全部库存保持不变）
- 归属三分：库位 / 运输中 / 机台内
- 数量为 0 即整行删除；同量覆写仍更新托盘号与事件号（保证直查与快照指向同一行）
- 账本合计变化时**事件驱动**推进水位统计

### 特点 5：库存预警作为可调优的工程量

平台实现了完整的库位水位管理闭环：

- **五态水位**：空库 / 低库存 / 正常 / 高库存 / 满库，带**滞回带**（默认 5% 容量）防抖动
- **水位统计**：按账面变化边沿累计空/满/低/高时长与触达次数（8 项 KPI）
- **水位建议**：仿真收尾自动产出 `water_mark_suggestions.json`，按「再订货点 = 消耗速率 × 补料提前期 × (1+安全系数)」计算，多种子取 p75
- **停滞报告**：仿真收尾产出 `stall_report.json`，区分「满且无消费方 / 机台饿等库位 / 成品库等收货」三类，并区分活动预警与已解除
- **建议回写**：网页可一键把建议导回库位表单，形成「仿真 → 建议 → 改参数 → 再仿真」的闭环

### 特点 6：离散事件仿真内核

`Simpy/Common/` 39 个模块不是 Demo，而是可复用的工业仿真内核：

- **多物料/BOM 装配**：合成器、旁路供件、旁路反压、账本门闩
- **批次策略**：整批 / 连续两种占用语义（整批单轮占用 = 标定工时 × 件数；连续单轮 = 标定工时，不倍乘）
- **节拍流水**：按入口间隔串行收料、按件驻留、并行容量限流
- **可靠性**：MTBF 采样故障、MTTR 采样修复、废品率、换型时间
- **交通管制**：滚动预约的点/边/声明区锁表，双向尽头、站点独占、先到先得
- **派工策略族**：选车（fifo / nearest）+ 出队（fifo / 模拟退火 sa / 禁忌搜索 tabu / 遗传算法 ea）四策略，统一以「空驶代价合计」为对比指标
- **AGV 电量**：按米耗电、按次举升耗电、每小时空闲耗电、低电返航充电

### 特点 7：事件唤醒机制

内核用 `WakeSignalRegistry` 做条件唤醒：**凡改动相关状态一律 Notify，由 30 秒看门狗兜底避免漏醒**。

长窗口仿真（8 小时及以上）因此能做到事件驱动而非固定步长轮询，性能显著。

### 特点 8：可扩展的引擎分流架构

仿真入口 `kernel_playback_sim.py` 按场景中的 `sim_engine` 字段分流：

- `existing_simpy`（缺省）→ 自研内核 `generic_playback_sim.py`
- `prodsys` →  prodsys 1.2.0 引擎（独立虚拟环境，子进程调用）

**新场景只需沿这个入口扩展，不再另建 `*_playback_sim.py` 作为主入口。** 这让「自研内核」与「prodsys 引擎」可以在某些情况下做同场对照验证。

### 特点 9：导航图体系

导航点带 `OwnerType`（AGV / Worker / Player）与 `PointType`（停车点 / 库位点 / 步行点 / 工位点 / 停止点 / 终点），三套默认导航图（`agvGraph` / `workerGraph` / `playerGraph`），可创建分组。

保存场景前会校验「运输体绑定的导航图与导航点归属一致」，不一致直接阻断保存并给诊断信息。

### 特点 10：生产级的回归测试与闸门

- **62 个 Python 回归脚本 / 19,947 行**，按主题组织（AGV 冲突、装配线、批次节拍、BOM、运输、交通、工人、厂外 IO、快照、水位、灌装线…）
- **冻结夹具库**（`scene_fixtures.py`）：性能基线与后续导出解耦，防夹具漂移
- **多维闸门脚本**：KPI 目录双份同名同序校验、三层键集对齐校验、网页声明校验、库位水位表单校验

### A.2 Framework / QFramework 业务框架 ✅

平台业务层，注册在 QFramework 架构 `ProdLineSim` 上。

#### 四个 Model（状态中枢）

| Model | 职责 | 关键能力 |
|-------|------|----------|
| **SimStateModel** | 仿真运行态总开关 | `IsRunning` / `IsSiming` / `TimeScale` / `ContinueTimeScale` / `StartTime` |
| **RTESceneManagerModel** | 场景窗口与显示设置 | 数量目标、时间目标、地面显隐、产品流向开关与实例上限、设备高亮开关、导航图显示、回放文件与绑定 |
| **DeviceRealtimeDataModel** | 设备实时数据缓存 | 设备 ID → 字段 key → 值；`WorkMode` 区分本地模拟/外部数据；`OnDeviceFieldsWritten` 统一通知口（回放与实时共用） |
| **StorageWarningModel** | 库存预警状态机 | 预警态 = f(库存值, 容量, 阈值) 纯函数 + 滞回；五态文案；帧批评估 |

#### 三个 System（行为调度）

| System | 职责 |
|--------|------|
| **SimLifecycleSystem** | 暂停 / 继续 / 倍速设置 |
| **RTEUISystem** | 设备浮动面板的创建、回收、统一显隐；15 个可映射字段；按世界距离缩放可见性；状态高亮查表 |
| **DataCollectSystem** | 统一采样调度（默认 1 秒间隔）、事件日志、资源指标记录 |

#### 配置体系

五份 JSON 配置，统一加载优先级：

```text
① RTEConfigLoader 事件链（工程根 Configs/）
② 磁盘自加载兜底：按工程约定的 Configs 检索顺序回退
③ 内置默认值
```

| 配置 | 内容 |
|------|------|
| `ProjectConfig.json` | 项目名、运行环境（编辑器/本地/发布）、调试模式、**运行模式（本地模拟 / 外部数据接入）**、全局更新时间 |
| `HTTPConfig.json` | HTTP 基址、Token 接口路径与账号、超时、请求模式（Json/Form） |
| `WebSocketConfig.json` | WebSocket 地址、Token、自动重连、心跳 |
| `StorageWarningConfig.json` | 库存预警总开关、默认高低水位、滞回 5%、高亮颜色、总览面板开关 |
| `DeviceStatusMappingConfig.json` | 外部状态映射、高亮组配置 |
| `DeviceInfoConfig.json` | 浮动面板显示字段清单 |

> **已知遗留**：`RTEConfigLoader` 事件链在常规编辑工作流中实测不触发，各配置类已加磁盘自加载兜底；`ProjectConfig` / `HTTPConfig` / `WebSocketConfig` 的运维配置路径未彻底收口（登记为方案总账 U2）。

#### 网络层（HTTP / WebSocket）

- **HTTPManager**：短连接请求队列**串行发送**（避免并发占用与乱序）、优先级（普通/优先）、Bearer Token 鉴权
- **DevicePreviewPollingService**：周期拉取设备列表写入 `DeviceRealtimeDataModel`
- **WebSocketUnityClient**：可复用骨架，网络线程与主线程隔离，自动重连、心跳、请求头、子协议
- **WebSocketDeviceDataHandler**：解析 `deviceData` / `devicePreview` 消息，与 HTTP 轮询共用同一缓存

### A.3 Main/Runtime 领域层（Domain）✅

运行态领域对象与行为，是三维场景里「会动的东西」。

#### 设备域（Device）

| 类型 | 说明 | 状态 |
|------|------|------|
| **ProdProcessor**（处理器 / 机台） | 加工机台核心。拉料 → 加工 → 推料；动画与回放倍速联动；空闲拆分（无料记饥饿、有料记等资源） | ✅ |
| **ProdBufferQueue**（暂存区 / 库位） | 堆栈规则（水平排列/竖直堆叠/不叠加）、FIFO/LIFO、库位水位契约字段、托盘预制体挂接 | ✅ 可代替发生器、吸收器功能 |
| **ProdGenerator**（发生器） | 物料发生器，固定间隔投放、生成数量上限 | 🔧 正在开发，到达时间表/到达序列未做 |
| **ProdReceiver**（吸收器） | 规划中的物料吸收器 | ⛔ 待开发 |
| **InputOutput**（输入输出） | 输入输出数值与比率的数据壳 | 🔧 正在开发 |

**ProdDevice 基类能力（状态机）**：

```text
空闲 Idle / 上料中 Loading / 正常生产 Processing / 下料中 DownLoading
暂停 Paused / 阻塞 Blocked / 等待 Waiting / 满载生产 FullyProcess
故障 Faulted / 急停 EmergencyStop / 维护 Maintenance / 准备 Setup
切换 Changeover / 复位 Resetting / 离线 Offline / 移动 Moving
转向 Turning / 非排班 NonScheduled
```

- **时间统计**：开时间、总加工、总阻塞、总满载、总空闲、总饥饿、总等资源；超限判定
- **时间分布规格**：准备时长与加工时长支持常数 / 均匀 / 三角 / 指数四种分布（与网页工艺配置对齐）
- **物料四列表**：已上料 / 加工中 / 下料中 / 已下料
- **导航点关联**：设备 ↔ 导航点双向关联（供自动路径与派车使用）
- **展示模式**：外部数据模式下设备不参与仿真计算，只显示远程状态
- **快照扩展**：写入 `state.code`、`state.raw`、`wip.inMachine`、`time.totalStarved` 等字段

#### 运输域（Transport）

| 能力 | 说明 |
|------|------|
| **运输体状态机** | 待机 Standby / 空闲 Free / 移动到点位 MovePoint / 移动到坐标 MovePos / 旋转 Rotate / 等待 Waiting / 抬升 Lift / 降下 Lower |
| **路径命令队列** | 移动到坐标 / 移动到点 / 按 ID 移动到点 / 旋转 / 等待 / 举放，按方向夹角自动插入旋转，按点位类型自动插入举放 |

#### ParametricConveyor —— 参数化传送带 ✅

**核心思路**：用「入口点 + 途经点 + 尾点」定义路径，系统派生**曼哈顿（正交）路径**，再按「直线皮肤 / 90° 转角皮肤」实例化外观。

|------|------|

| **失败原因诊断** | 7 类：控制点不足 / 高度差超限 / 缺出带方向 / 尾点不应有出带方向 / 反向或投影过短 / 点重合 |
| **几何参数** | 宽度（默认 0.4m）、高度（默认 0.9m）、传输速度（组件默认 0.3 m/s，文档默认 0.25 m/s）、库位取件间隔 |
| **自动派生指标** | 传输时长由路径长度 + 速度派生，不设第二真源 |
| **皮肤实例化** | 直线段与 90° 转角各一套预制体模板，转角按弧线分段（16 段）保证弧长误差可控；腿部可调高但皮带厚度不变 |
| **可视化** | ALINE 绘制路径 + 分段选择碰撞代理 + Gizmos |
| **文档往返** | 写入 `conveyor_layout_list`（与初始化对象同级，不污染主键），支持导入导出 |
| 限制🔧 | **目前仅支持等高平面**，升降与坡段未实现 |

**命令行参数**：场景 JSON、仿真时长、随机种子、快照间隔、回放输出、场景输出、报告输出、输出目录。

### 通用编排器 `generic_playback_sim.py`

**文件头 29 行逐条声明装配规则**（权威清单）：

1. 认到货来源（发生器 / 到货表）；KPI 机台清单必填
2. KPI 统计项非空时只保留勾选且已统计的机台
3. 合法非空批次策略 → 满载门闩；空策略 → 单件流
4. 空策略 + 最小入口间隔 > 0 → 节拍流水（两者互斥）
5. 后继路由：有传送带走传送带；声明两端库且无正时长传送带走工序间搬运；否则瞬时直达
6. 非空装配参数 → 组装账本门闩
7. 码垛取件数 → 单轮码放 + 成托累计
8. 运输分组 → 运输实例；单趟容量（周期清库）/ 间隔拉运 / 回退末工序标量工时
9. 承运池 → 池共用空闲实例池
10. 交通管制开启 → 发车前路径意图预约
11. 派工开启 → 请求入队再派车
12. 托盘池开启 → 空盘占位
13. 厂外 IO 开启 → 周期写入/扣减库位
14. 虚拟供件开启 → 工艺边界不占库存
15. 物料投放=原料库 → 到达只写补料循环源库
16. 上料库声明 → 工人上料
17. 有上料的整批机订单走候槽，WIP 只认上料写入

**输出产物 5 类**：回放 JSON、场景回写 JSON、KPI 报告、水位建议、停滞报告。

### 派工策略族（四策略）✅

**两个独立维度**：

| 维度 | 取值 |
|------|------|
| 选车策略 `vehicle_policy` | `fifo`（缺省）/ `nearest`（到源库导航代价最小） |
| 出队策略 `request_policy` | `fifo`（缺省）/ `sa` / `tabu` / `ea` |

| 策略 | 算法 | 参数 |
|------|------|------|
| **sa** 模拟退火 | 相邻交换，24 轮，温度按 0.9 降温，`delta ≤ 0` 或按指数概率接受，全程记最优 | 内置固定参数，不进场景数据 |
| **tabu** 禁忌搜索 | 每轮枚举全部相邻交换按代价升序（保证确定性），禁忌键为被换两请求的无序对，禁忌期 5 轮，**优超历史最优可破禁** | 24 轮 |
| **ea** 遗传算法 | 种群 16、代数 20、精英 2、锦标赛 K=3、变异率 0.2、顺序交叉（OX）；初始 1 个当前序 + 15 个随机洗牌 | — |

**对比指标统一为「空驶代价合计」**（不可比步加罚值 1e9），三策略共用「候选数 ≥ 2 且存在可比图」的改序门槛。**并发度不因策略而变**（各策略均按空闲车数并发派趟）。

## C.10 AGV 路径冲突检查 ✅

**离线工具**（2105 行），不修改回放文件、不接入 RTE 运行态。

**9 类冲突 + 两级严重度**：

| 类别 | 严重度 | 判定 |
|------|--------|------|
| **对向会车** | ❌ 错误 | 无向边归一后区间重叠 |
| **同向占边** | ❌ 错误 | 同一条边同时被两车占用 |
| **同点占用** | ❌ 错误 | 两车在同一导航点重叠 |
| **活动任务长期无推进** | ❌ 错误 | 阈值 `max(30, min(300, 分析时长×5%))` 秒 |
| **载货后长期未卸货** | ❌ 错误 | 同阈值 |
| **车辆等待环** | ❌ 错误 | wait-for 图找环 |
| **库位-导航未对应** | 混合 | 7 个子类：未绑导航点（警告）、点在图中不存在（错误）、点指向别的库位（错误）、点设备码为空（警告）、平面距离超限（警告）、库位在初始化列表不存在（警告）、库位未含该点（错误） |
| **上下料未对应** | ⚠️ 警告 | 取货未关联、卸货未关联、同点未关联、出口点用在取货、目的角色不符 |
| **同点途经** | ⚠️ 警告 | 两车重叠不超过一个采样步（`collision_point_pass`） |
| **空间过近** | ⚠️ 警告 | 按插值位置算最近距离小于碰撞半径；**距离为 0 按真实最小值写出**（不再记成下一拍的 1.414 或 2 米） |

**输出 5 类文件**：AGV 抽取 JSON、冲突报告 JSON、冲突明细 CSV、中文报告 MD、英文报告 MD。

**业务约定**：机台转运取货对应 `{机台}-OUT`，卸货对应下一工序 `{机台}-IN`；空托盘视为车载空盘逻辑取货；返航充电不计入上下料检查。

## D. 数据契约与工具

### D.1 场景 JSON 4.0.0 ✅

**顶层结构**：`meta` + `scene`

| 段 | 内容 |
|----|------|
| **meta**（14 字段） | 架构版本、生成器、创建时间、时间单位、显示纪元、仿真起止、随机种子、快照间隔、产线编码，**4.0.0 新增 7 个**：仿真引擎、到货来源、KPI 机台清单、KPI 统计项清单、统计项选择模式、统计项分组清单、统计项单项清单 |
| **scene**（7 键） | 场景名、场景 UUID、**导航图列表**、**初始化对象列表**、**传送带布局列表**、场景模型资源名、产品流向显示预设、**工艺表** |

**工艺表（15 键，权威顺序）**：

```text
工艺路线 / 到货表 / 订单 / 在制品上限
/ BOM / 机台产品 / 产品 / 装配
/ 班次模型 / 机台 / 库位
/ 员工分组 / 工人 / 运输分组 / 运输单位
/ 传送带传输边
```

**关键设计**：
- 四类派生数据（产品 / BOM / 机台产品 / 装配）由工艺路线派生，**持久化时不写入工艺表**，避免双向不一致
- 传送带传输边为透传键（RTE 采集，网页不编辑不计算时长）
- 行级软开关：导出会剔除 `enabled=false` 的行，引擎不认该字段
- 编辑态专用键禁止导出
- **兼容性**：新建默认 4.0.0，导入兼容 3.2.0 及以上；旧文件不改不升版本

### D.2 回放 Playback JSON 4.0.0 ✅

**结构**：`meta` + `scene` + `timeline[]`

**九种回放事件类型**：

```text
MachineStateChanged        机台状态变更（开始/完成加工）
LotCreated / LotCompleted  批次创建 / 完成
MoveSegmentStarted/Completed  移动段开始 / 完成
TurnStarted / Completed       转弯开始 / 完成
ConveyorTransferStarted/Completed  传送带交接开始 / 完成
```

**变更集结构**：目标类型、目标 ID、字段字典、变换增量（起点→终点）；**快照记录**：周期性写出机台、承运实例、工人、库位后态，**库位快照带预警级别**。

**库位水位四字段**（可缺省）：预警开关、判定模式、低水位、高水位；另有满库整清开关。**旧文件不改、不升版本；缺省即关闭。**
