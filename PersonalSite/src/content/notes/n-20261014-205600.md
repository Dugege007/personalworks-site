# 表格型 CUSUM：抓住过程均值的小幅持续偏移

**表格型累积和控制图（tabular CUSUM，Cumulative Sum）**专门对付「每次只漂一点点，但一直往同一边漂」的均值阶跃。机制和 EWMA、孤立森林都不一样：Shewhart 控制图要单点跳出 ±3σ 才报警；小偏移时单点几乎看不出来，CUSUM 把偏差一块一块累起来，累过决策间隔就报。

## 是什么

E. S. Page 在 1954 年的论文 *Continuous inspection schemes*（*Biometrika* 41(1/2):100–115）提出用累积和做连续检验。每个观测相对目标均值的偏差不断加总：过程对准目标时，和在零附近晃；均值一旦抬高或压低，和就朝一侧漂。

工程上更常用的是 **表格型（tabular）双侧 CUSUM**。它和早期文献里的 V 形掩模（V-Mask）等价，但用两行递推代替在图上滑动掩模。NIST *Engineering Statistics Handbook* 6.3.2.3 写明：相对 Shewhart，CUSUM 在要抓「大约 2σ 或更小」的均值偏移时更灵敏。Montgomery 的经验法则（NIST 原文引用）是：设计时常取容许间隙 \(k=\delta/2\)（标准化后常取 \(k^*=0.5\)），决策间隔 \(h\) 大约取 4 或 5。

和 EWMA 的差别可以收成一句：两者都有记忆；EWMA 是指数衰减加权后再设阈值，CUSUM 是带反射壁（到零就停）的累积和，参数 \(k\)、\(h\) 直接对应你打算抓多大的阶跃 \(\delta\)。下文不再展开 EWMA。

## 怎么工作

### 表格公式（以 NIST 为准）

记目标均值 \(\mu_0\)、容许间隙（allowance）\(k\)、决策间隔 \(h\)。对观测序列 \(x_i\)：

\[
\begin{aligned}
S_{\mathrm{hi}}(i) &= \max\bigl(0,\; S_{\mathrm{hi}}(i-1) + x_i - \mu_0 - k\bigr) \\
S_{\mathrm{lo}}(i) &= \max\bigl(0,\; S_{\mathrm{lo}}(i-1) + \mu_0 - k - x_i\bigr)
\end{aligned}
\]

初值 \(S_{\mathrm{hi}}(0)=S_{\mathrm{lo}}(0)=0\)。任一方超过 \(h\) 就判定过程失控。\(S_{\mathrm{hi}}\) 抓向上偏移，\(S_{\mathrm{lo}}\) 抓向下偏移。\(\max(0,\cdot)\) 是反射壁：反向的小波动不会把统计量拖到负半轴，避免「先欠债再还」。

### 标准化写法

先令 \(z_i=(x_i-\mu_0)/\sigma\)，再对 \(z\) 做同样的递推，此时目标为 0，参数写成 \(k^*\)、\(h^*\)。要抓大约 \(1\sigma\) 的阶跃时，Montgomery / NIST 经验法则常取 \(k^*=0.5\)、\(h^*=4\) 或 \(5\)。演示脚本用标准化版，读数更直接。

原始量纲与标准化量纲可以互换：若 \(\sigma\) 是单点标准差，则 \(k=k^*\sigma\)、\(h=h^*\sigma\)；若监控的是样本均值，就把 \(\sigma\) 换成 \(\sigma_{\bar{x}}\)。

### 和 Shewhart 的差别

Shewhart 单点规则是 \(|x_i-\mu_0|>3\sigma\) 才报。若真实均值只抬高 \(0.75\sigma\)，单点落在 3σ 外的概率仍然很小，往往要等很久才碰巧跳出。CUSUM 每一步只把「超出容许间隙 \(k\) 的那一小截」累进去；连续同向漂时 \(S_{\mathrm{hi}}\) 会稳步爬升，直到越过 \(h\)。

### NIST 教科书例子（权威复现）

NIST 给出 20 个样本均值（每个样本大小 \(n=4\)）：

324.925, 324.675, 324.725, 324.350, 325.350, 325.225, 324.125, 324.525, 325.225, 324.600, 324.625, 325.150, 328.325, 327.250, 327.825, 328.500, 326.675, 327.775, 326.875, 328.350

目标 \(\mu_0=325\)；过程标准差 1.27，故 \(\sigma_{\bar{x}}=1.27/\sqrt{4}=0.635\)。按 \(\alpha=0.0027\)、\(\beta=0.01\)、\(\delta=1\) 设计得 \(k=0.3175\)、\(h\approx 4.1959\)。脚本按 NIST 表格公式复算：

| 样本（1-based） | \(x\) | \(S_{\mathrm{hi}}\) | \(S_{\mathrm{lo}}\) |
|---|---|---|---|
| 1 | 324.925 | 0.0000 | 0.0000 |
| 5 | 325.350 | 0.0325 | 0.0000 |
| 12 | 325.150 | 0.0000 | 0.0000 |
| 13 | 328.325 | 3.0075 | 0.0000 |
| **14** | **327.250** | **4.9400** | 0.0000 |
| 15 | 327.825 | 7.4475 | 0.0000 |
| 20 | 328.350 | 19.0350 | 0.0000 |

第 14 个点 \(S_{\mathrm{hi}}=4.94>h\)，与 NIST 表格一致（表中约 4.94，并写明 point 14 为首个失控信号）。第 13 点已经大幅上跳，但累积量尚未越过 \(h\)；第 14 点继续偏高，才触发报警。

## 复杂度和代价

- **时间 / 空间**：每来一个点只做几次加减和两次 `max`，时间 \(O(1)\)；只需存两个状态量，空间 \(O(1)\)。
- **参数与 ARL**：平均运行长度（Average Run Length，ARL）是「到报警为止平均要看多少个点」。受控时希望 ARL₀ 大（少误报），失控时希望 ARL₁ 小（快检出）。\(k\) 大致按要抓的偏移 \(\delta\) 的一半来取；\(h\) 越大越迟钝、误报越少。脚本对标准化 \(k^*=0.5\)、\(h^*=5\) 做了 200 次受控蒙特卡洛（单次最长 5000 点）：ARL₀ 均值约 500、中位数 330，量级就是「几百个点才误报一次」。
- **局限**：
  1. 对「突然跳很大」的单点尖峰，Shewhart 往往更快；CUSUM 的优势在小幅持续偏移。
  2. \(\mu_0\)、\(\sigma\) 估错会系统性偏敏感或偏迟钝，需要先有一段受控数据定标。
  3. ARL₀ 有限，长序列上几乎总会出现误报；工业上报警后常把 \(S_{\mathrm{hi}}\)、\(S_{\mathrm{lo}}\) 复位到 0 再继续盯。
  4. 方差变化、强自相关、多变量耦合都不在这一版单变量均值 CUSUM 的假设里。

## 应用场景

1. **产线尺寸、温度、压力的慢性漂移**：刀具磨损、冷却液变差、温控缓慢失调，每步只有零点几 σ，但方向稳定。
2. **数字孪生里判断过程是否仍对准标称**：仿真与实机对齐后，用 CUSUM 盯关键均值是否开始爬。
3. **股票均价的缓慢抬升或下移**（副业向）：把日收益或短窗均价相对基准做标准化 CUSUM，对「连续多日同向偏」比单日 3σ 更敏感。这只是监测工具，不是交易策略。
4. **与 Shewhart 并用**：大跳用 Shewhart，小漂用 CUSUM，两套图一起挂在看板上很常见。

## 实例：主轴温度 +0.75σ 均值阶跃

脚本（SEED=42）模拟主轴温度：目标 \(\mu_0=55\)℃，\(\sigma=0.4\)℃，共 1800 秒。前 900 秒受控；从第 900 秒起均值抬到 \(55+0.75\times 0.4=55.3\)℃。标准化 CUSUM 取 \(k^*=0.5\)、\(h^*=5\)，报警后复位；对照 Shewhart ±3σ。

实测：

- **CUSUM** 在阶跃后第 **9** 秒首次报警（\(t=909\)，\(S_{\mathrm{hi}}\approx 5.17\)）。
- **Shewhart** 在阶跃后第 **169** 秒才首次越过 ±3σ（\(t=1069\)）。
- 阶跃前 CUSUM 有 3 次误报（\(t=260,443,698\)），Shewhart 有 5 次。这与「ARL₀ 大约几百」并不矛盾：900 个受控点里出现几次误报是预期内的，所以现场要复位、合并告警或再加确认规则。
- 另跑一条纯受控序列（\(n=1800\)，seed=43）：CUSUM 报警 4 次，Shewhart 5 次。
- 同一随机种子、偏移改为 +1.0σ 时：CUSUM 延迟 **5** 秒，Shewhart 延迟 **66** 秒。

图上方面板是温度曲线、目标线与 Shewhart 限，竖线标出阶跃时刻与 CUSUM 阶跃后首报；下方面板是 \(S_{\mathrm{hi}}\)、\(S_{\mathrm{lo}}\) 与 \(h^*=5\)。灰色虚线标出阶跃前的 CUSUM 误报位置。

## 代码

Python（示例脚本里的核心递推）：

```python
def tabular_cusum(xs, mu0, k, h, reset_on_alarm=False):
    s_hi = s_lo = 0.0
    shi, slo, alarms = [], [], []
    for i, x in enumerate(xs):
        s_hi = max(0.0, s_hi + x - mu0 - k)
        s_lo = max(0.0, s_lo + mu0 - k - x)
        shi.append(s_hi)
        slo.append(s_lo)
        if s_hi > h:
            alarms.append((i, "hi", s_hi))
            if reset_on_alarm:
                s_hi = s_lo = 0.0
        elif s_lo > h:
            alarms.append((i, "lo", s_lo))
            if reset_on_alarm:
                s_hi = s_lo = 0.0
    return shi, slo, alarms


def standardized_cusum(xs, mu0, sigma, k_star, h_star, reset_on_alarm=False):
    zs = [(x - mu0) / sigma for x in xs]
    return tabular_cusum(zs, mu0=0.0, k=k_star, h=h_star, reset_on_alarm=reset_on_alarm)
```

跑 NIST 例子时用原始量纲 \(k=0.3175\)、\(h=4.1959\) 且不复位；跑主轴演示时用标准化 \(k^*\)、\(h^*\) 并在报警后复位。

## 延伸思考

- 快速初始响应（FIR，Fast Initial Response / head start）：一开始把 \(S\) 设成 \(h/2\)，对新开线或刚复位后的偏移更敏，代价是短期误报率上升；
- 用 ARL 表或马尔可夫链精确标定 \(h\)，而不是只用 4 或 5 的经验值；
- CUSUM 盯方差、盯泊松计数，以及多变量 MCUSUM；
- 和 EWMA 在相同 ARL₀ 下比 ARL₁（谁在 0.5σ、1σ、2σ 处更快）；
- 自相关过程上直接套独立假设的 CUSUM 会怎样，要不要先建模残差再对残差做 CUSUM。
