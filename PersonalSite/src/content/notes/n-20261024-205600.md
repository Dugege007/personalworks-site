# 三次贝塞尔缓动：CSS cubic-bezier 如何把时间弯成「先慢后快再慢」

## 是什么

网页过渡与关键帧动画里，属性并不是按墙钟时间匀速变到终点。CSS 用**缓动函数（easing function）**把输入进度（通常是已播放时间占总时长的比例 \(u\in[0,1]\)）映射成输出进度 \(y\)，再用 \(y\) 去插值颜色、位移、透明度或仪表读数。W3C 的 *CSS Easing Functions Level 1*（Candidate Recommendation Draft，2023-02-13）把一类常用缓动写成三次贝塞尔：端点固定为 \(P_0=(0,0)\)、\(P_3=(1,1)\)，作者只指定两个控制点 \(P_1=(x_1,y_1)\)、\(P_2=(x_2,y_2)\)，写作 `cubic-bezier(x1, y1, x2, y2)`。其中 \(x_1,x_2\) 必须落在 \([0,1]\)，否则声明无效；\(y\) 可以越出 \([0,1]\)，用来做出冲过终点再回落的过冲感。

规范还把几个关键字钉死成固定控制点：

| 关键字 | 等价 `cubic-bezier` |
|---|---|
| `ease` | `(0.25, 0.1, 0.25, 1)` |
| `ease-in` | `(0.42, 0, 1, 1)` |
| `ease-out` | `(0, 0, 0.58, 1)` |
| `ease-in-out` | `(0.42, 0, 0.58, 1)` |
| `linear` | 恒等映射（输出＝输入） |

三次贝塞尔曲线本身是 CAGD（计算机辅助几何设计）里的标准对象。Gerald Farin 等人的教材用 Bernstein 多项式与 **de Casteljau 算法**给出求值与细分；下文演示同时用闭式 Bernstein 公式与 de Casteljau 交叉核对。Unity 的 `AnimationCurve`、Three.js 的缓动／关键帧曲线，以及前端 CSS，都是在「时间轴 → 输出进度」这一层复用同一几何。

## 怎么工作

### 直觉画面

把单位正方形想成一张「时间—进度」图纸：横轴是墙钟进度 \(u\)（播了百分之几），纵轴是画面上真正用的进度 \(y\)（属性走到百分之几）。直线对角线就是线性插值：播到一半，数值也到一半。把两个控制点往里拽，曲线会鼓成「两头平、中间陡」或「一头陡、一头平」——眼睛看到的就是先慢后快、先快后慢，或先慢后快再慢。

关键坑在这里：**曲线是用参数 \(t\) 画出来的**，点是 \(B(t)=(x(t),y(t))\)。CSS 缓动要的不是「给定 \(t\) 取 \(y(t)\)」，而是「给定横轴上的 \(u\)，找到曲线上 \(x(t)=u\) 的那一点，再读它的 \(y\)」。\(x_1,x_2\in[0,1]\) 保证 \(x(t)\) 关于 \(t\) 单调，这个反解才是函数。直接写 `y = By(u)` 会和浏览器不一致。

### 形式定义（挂回直觉）

三次贝塞尔（Bernstein 形式，Farin *The Essentials of CAGD*）：

\[
B(t)=\sum_{i=0}^{3} P_i\,\binom{3}{i}(1-t)^{3-i}t^{i},\qquad t\in[0,1].
\]

对 CSS 缓动，\(P_0=(0,0)\)、\(P_3=(1,1)\)，于是

\[
\begin{aligned}
x(t)&=3(1-t)^2 t\,x_1+3(1-t)t^2\,x_2+t^3,\\
y(t)&=3(1-t)^2 t\,y_1+3(1-t)t^2\,y_2+t^3.
\end{aligned}
\]

**de Casteljau**：从控制多边形出发，反复按比例 \(t:(1-t)\) 切分边，三轮后得到的唯一点即 \(B(t)\)。数值上比直接展开高次项更稳，也顺带给出切线与细分控制点。

**CSS 求值**：对输入进度 \(u\)，用牛顿法（配合二分兜底）解 \(x(t)=u\) 得 \(t^\*\)，再输出 \(y(t^\*)\)。规范正文写的是「输入进度当作曲线的 \(x\)，输出进度取对应的 \(y\)」，评价细节指向计算机图形学教材（如 Shirley 等 *Fundamentals of Computer Graphics*）。

### 可核对的小例子（演示设定）

脚本参数写死（`SEED=42`，本演示无随机采样，SEED 仅作可复现约定）：

- 对照曲线：`ease-in-out`＝`(0.42, 0, 0.58, 1)`；另画 `ease-out`＝`(0, 0, 0.58, 1)` 表示「先快后慢」。
- 线性基线：输出进度 \(y=u\)。
- 仪表盘实例：数值从 \(0\) 动画到 \(1000\)，时长 \(1.0\,\mathrm{s}\)，显示值 \(=0+1000\cdot y(u)\)，\(u=t_{\mathrm{wall}}/1.0\)。

在 \(u\in\{0,0.25,0.5,0.75,1\}\) 处，`ease-in-out` 与线性的输出进度为：

| \(u\)（墙钟） | 线性 \(y\) | ease-in-out \(y\) | 差值 |
|---:|---:|---:|---:|
| 0.00 | 0.000000 | 0.000000 | 0.000000 |
| 0.25 | 0.250000 | 0.129162 | −0.120838 |
| 0.50 | 0.500000 | 0.500000 | 0.000000 |
| 0.75 | 0.750000 | 0.870838 | +0.120838 |
| 1.00 | 1.000000 | 1.000000 | 0.000000 |

对称控制点使中点与线性重合；四分之一处落后约 \(0.121\)，四分之三处超前同样幅度——正是「两头慢、中间补回来」的几何后果。参数 \(t=0.5\) 时 de Casteljau 与闭式公式都给出 \(B=(0.5,0.5)\)，与牛顿反解 \(x(t)=0.5\) 一致。

同设定下 `ease-out` 在 \(u=0.25\) 时 \(y\approx 0.378138\)（已快过线性），在 \(u=0.5\) 时 \(y\approx 0.684643\)。

## 复杂度和代价

- **每次求值**：固定次数的牛顿迭代（演示约 12 步）加若干次三次多项式；浏览器引擎对常用关键字有查表或专用路径，自定义 `cubic-bezier` 仍是常数时间。
- **存储**：四个浮点控制点；Unity／Three.js 曲线若改成多段关键帧，代价随段数线性增长。
- **实现陷阱**：若误用 \(y(u)\) 而非「对 \(x\) 反解再取 \(y\)」，曲线在控制点 \(x\) 偏离对角线时会与 CSS 偏差明显。\(x_1,x_2\) 越界时规范视为无效，不应静默夹紧后当对的用。
- **过冲**：\(y_1\) 或 \(y_2\) 越出 \([0,1]\) 时输出可暂时小于 0 或大于 1；颜色分量等属性会被裁剪，位移则可能真的冲出再回来。

## 应用场景

- **网页 UI**：按钮悬停、抽屉展开、路由切换的 `transition-timing-function`／`animation-timing-function`；设计稿里常见「不要匀速滑，要 ease」。
- **产线／数字孪生仪表盘**：KPI、温度、节拍达成率从旧值滚到新值；`ease-out` 先快后慢适合「数字蹦出来再稳住」，`ease-in-out` 适合面板整体淡入淡出。
- **Unity／Three.js**：用与 CSS 相同的控制点驱动 `AnimationCurve` 或自定义缓动，保证 Web 看板与三维孪生里同一条「手感」曲线。
- **旁例**：相机跟焦的时间重映射、进度条、骨架屏渐显，凡是「时间轴上的非线性」都可以先试三次贝塞尔再上弹簧物理。

## 实例二：产线仪表盘「先快后慢」

把右图里的 `ease-out`（`(0, 0, 0.58, 1)`）读成节拍达成率从 0% 滚到目标。墙钟 \(0.25\,\mathrm{s}\) 时线性仍显示 \(250\)，`ease-out` 已到约 \(378.1\)；半秒时线性 \(500\)，`ease-out` 约 \(684.6\)。前半段数字跳得更快，后半段明显刹住，适合大屏上「先报出量级、再精细收敛」的观感。同一套函数也可写成 CSS：

```css
.kpi-roll {
  transition: --kpi 1s cubic-bezier(0, 0, 0.58, 1);
}
```

或在 JS 里每帧取 `u = elapsed / duration`，调用与脚本相同的反解得到 `y`，再 `value = from + (to - from) * y`。三维孪生里把 `y` 喂给 Unity `AnimationCurve.Evaluate` 的等价自定义曲线即可对齐 Web 端。

## 短代码（CSS 语义的一次求值）

```python
# P0=(0,0), P3=(1,1); 先解 x(t)=u，再取 y(t)
def bezier_x(t, x1, x2):
    u = 1 - t
    return 3*u*u*t*x1 + 3*u*t*t*x2 + t*t*t

def bezier_y(t, y1, y2):
    u = 1 - t
    return 3*u*u*t*y1 + 3*u*t*t*y2 + t*t*t

def ease_css(u, x1, y1, x2, y2, iters=12):
    t = u
    for _ in range(iters):
        x = bezier_x(t, x1, x2)
        # dx/dt of cubic with P0=0,P3=1
        dx = (3*(1-t)**2*x1 + 6*(1-t)*t*(x2-x1) + 3*t**2*(1-x2))
        if abs(dx) < 1e-9:
            break
        t = min(1.0, max(0.0, t - (x - u) / dx))
    return bezier_y(t, y1, y2)

# ease-in-out @ u=0.25  → 约 0.129162
```

## 局限和要注意的地方

1. **反解是必需步骤。** 教学图常画 \(B(t)\) 参数曲线；接到 CSS／Web Animations 时必须按 \(x\to y\) 映射实现。
2. **单段三次表达力有限。** 更碎的节奏（多段加速）要用多段贝塞尔、`linear()` 多停靠点，或弹簧模型。
3. **过冲与裁剪。** \(y\) 越界在 transform 上可见，在 `opacity` 等有界属性上会被夹紧，观感与曲线预览不完全一致。
4. **与物理弹簧不同。** 贝塞尔是时间重映射，不显式建模质量—阻尼；要「可打断、可接力」的手势跟随时，弹簧或 PID 式跟随往往更合适。

## 延伸思考

1. 固定 `ease-in-out` 的 \(x_1=0.42,x_2=0.58\)，只扫 \(y_1,y_2\)，观察中点是否仍落在 \(0.5\)，以及过冲何时出现。
2. 把牛顿迭代改成对 \(x(t)\) 的二分，比较在移动端每帧求值次数与误差 \(10^{-6}\) 下的耗时。
3. 用同一组控制点驱动 CSS transition 与 Canvas／WebGL 自绘数值，逐帧截图核对是否对齐。
4. 在数字孪生大屏上 A/B：线性、`ease-out`、轻微过冲的自定义曲线，记录运维人员对「数值可信／刺眼」的主观评分。
