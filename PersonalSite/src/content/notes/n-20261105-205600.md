## 是什么

**并查集**（Union-Find / Disjoint Set Union，简称 DSU）维护若干元素的互斥分组：任意时刻每个元素恰好属于一个集合，集合用一棵以「代表元／根」为根的树表示。三个基本操作是：

- **MakeSet(x)**：让 \(x\) 独自成集，父指针指向自己。
- **Find(x)**：沿着父指针走到根，返回 \(x\) 所在集合的代表元。
- **Union(a, b)**：若 \(a\) 与 \(b\) 根不同，就把一棵树挂到另一棵下，合并成同一集合；若根已相同，则这两点早已同集——在无向图里，这往往意味着「再加这条边会成环」。

朴素实现可以正确，但树可能退化成链，Find 变慢。工程上几乎总是同时打开两项优化：**路径压缩**（path compression）和**按秩合并**（union by rank）。Galler 与 Fischer 1964 年在 CACM 给出了早期树形并查表示；Tarjan 1975 年起系统分析了带压缩的均摊界；Tarjan 与 van Leeuwen 1984 年把多种链接／压缩策略的复杂度钉死在反 Ackermann 量级。

**本文范围：** 数组实现的路径压缩＋按秩合并、无向图连通分量与成环检测、产线故障域与队名别名归组两组可复现演示。**非范围：** 持久化／可回滚并查集、带权并查（边权差分约束）、动态删边的完全重构，以及 Kruskal 最小生成树的完整建堆流程——那些需要单独篇幅。

## 怎么工作

### 直觉画面

把每个集合想成一棵树：根是队旗，队员的父指针指向队长或中间干部。问「咱俩一队吗」就各自往上爬到队旗，比旗号。合并两队时，把一队的旗挂到另一队旗下面。爬得太深会慢，所以 Find 时顺便让沿途的人直接挂到旗下（路径压缩）；合并时尽量让矮的树挂到高的树下（按秩合并），避免树越合越高。

### 路径压缩

Find 第一次走到根之后，把路径上每个节点的父指针改成根（或改成祖父的隔代压缩变体）。压缩后，秩不再等于真实树高，而只是高度的上界——实现里**不要**在压缩时下调秩，否则按秩合并的论证会坏掉。

可核对对照：先手工把 **0..9** 链成 `parent[i]=i+1`（根为 9），不压缩时点 **0** 到根要 **9** 跳、点 **5** 要 **4** 跳；对点 0 做一次带压缩的 Find 后，整条链的父指针都变成 9，点 0 再到根只需 **1** 跳。

### 按秩合并

每个根维护非负整数 **rank**。合并两根 \(r_a,r_b\) 时：

1. 若 \(\mathrm{rank}[r_a] < \mathrm{rank}[r_b]\)，令 \(r_a\) 的父为 \(r_b\)；
2. 若 \(\mathrm{rank}[r_a] > \mathrm{rank}[r_b]\)，令 \(r_b\) 的父为 \(r_a\)；
3. 若相等，任选一方为新根，并把该新根的秩加 **1**。

秩相等才升高，保证秩是高度上界；配合路径压缩，单次操作的均摊代价降到反 Ackermann 级别。

### 可核对的玩具：元素 0..9

固定合并顺序（脚本常量，不随机）：

\[
(0,1),\ (1,2),\ (3,4),\ (5,6),\ (6,7),\ (3,5),\ (8,9)
\]

每次合并后的分量数从 10 降到 **3**。对全部元素做 Find（触发压缩）后：

| 元素 | 压缩后 parent | 根 |
| ---: | ---: | ---: |
| 0 | 0 | 0 |
| 1 | 0 | 0 |
| 2 | 0 | 0 |
| 3 | 3 | 3 |
| 4 | 3 | 3 |
| 5 | 3 | 3 |
| 6 | 3 | 3 |
| 7 | 3 | 3 |
| 8 | 8 | 8 |
| 9 | 8 | 8 |

三个连通分量（按根排序）：

- 根 **0**：`[0, 1, 2]`
- 根 **3**：`[3, 4, 5, 6, 7]`
- 根 **8**：`[8, 9]`

**成环检测：** 此时再请求 `Union(2, 0)`。Find(2) 与 Find(0) 都是 0，已经同集，合并返回失败——对应无向图里「这条边会成环」。脚本打印：`same=True, merged=False`。

## 复杂度和代价

- **空间：** 父指针数组与秩数组各 \(O(n)\)。
- **时间：** \(n\) 个元素上做 \(m\) 次 Find／Union，带路径压缩与按秩合并时，总代价 \(O(m\,\alpha(n))\)，其中 \(\alpha\) 是反 Ackermann 函数。对一切现实规模的 \(n\)，\(\alpha(n)\le 4\)，因此实践中把单次操作当成「近乎常数」。
- **对照：** 只有按大小／按秩合并、不做压缩时，单次 Find 最坏 \(O(\log n)\)；只有压缩、乱序链接时也有理论保证，但「压缩＋按秩」是教材与面试的标准搭配。
- **实现细节：** 递归 Find 在极深链上可能爆栈；演示用两遍迭代压缩（先找根，再把路径挂到根）。

## 应用场景

- **Kruskal 最小生成树：** 边按权排序后依次尝试加入；仅当两端不同集时 Union，否则跳过（会成环）。
- **无向图连通分量／成环：** 扫一遍边做 Union；最终根的个数即分量数；Union 失败即发现环。
- **产线／数字孪生故障域：** 设备与通信／供电链路建成图，一个连通分量就是一次局部故障可能波及的最大集合。
- **队名／别名归组：** 把「同义写法」当边 Union，组内选一个代表名展示，其余当别名挂上。

## 队名别名归组实例

固定 **12** 条写法，人工给出 **8** 对同义关系后 Union：

| 代表名 | 组内成员 |
| --- | --- |
| Manchester United | Manchester United, Man Utd, 曼联, Manchester Utd |
| Liverpool FC | Liverpool FC, Liverpool, 利物浦 |
| Arsenal | Arsenal, Arsenal FC, 阿森纳 |
| Chelsea | Chelsea, 切尔西 |

得到 **4** 组。代表名取组内原始列表中下标最小者；新平台来的别名只需与组内任一成员 Union，即可并入同一俱乐部集合，而不必先知道「常用名」是哪一个。

## 短代码（Python 核心类）

```python
class UnionFind:
    def __init__(self, n: int):
        self.parent = list(range(n))
        self.rank = [0] * n
        self.components = n

    def find(self, x: int) -> int:
        root = x
        while self.parent[root] != root:
            root = self.parent[root]
        while self.parent[x] != root:
            nxt = self.parent[x]
            self.parent[x] = root
            x = nxt
        return root

    def union(self, a: int, b: int) -> bool:
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False  # already same set → cycle if this was a new edge
        if self.rank[ra] < self.rank[rb]:
            self.parent[ra] = rb
        elif self.rank[ra] > self.rank[rb]:
            self.parent[rb] = ra
        else:
            self.parent[rb] = ra
            self.rank[ra] += 1
        self.components -= 1
        return True

uf = UnionFind(10)
for a, b in [(0,1),(1,2),(3,4),(5,6),(6,7),(3,5),(8,9)]:
    uf.union(a, b)
assert uf.components == 3
assert uf.find(2) == uf.find(0)
assert uf.union(2, 0) is False
```

## 局限和要注意的地方

1. **秩在压缩后只是上界。** 不要在 Find 里改 rank；需要真实高度时另做一次遍历。
2. **删边不是对称操作。** 并查集擅长加边合并，删掉一条边后分量是否分裂，一般要重建或改用更重的动态连通结构。
3. **有向图／强连通** 不能直接套这套「无向同集」语义；强连通要用 Tarjan／Kosaraju 等专门算法。
4. **代表元不稳定。** 根会随合并选边变化；对外展示需要时，在组内按业务规则另选「常用名」。
5. **并行与持久化。** 多线程同时 Union 要加锁或改用专用并发结构；需要历史版本时看持久化并查集文献。

## 延伸思考

1. 把玩具里的 `Union(3,5)` 改成先 `Union(3,8)` 再并其余边，画出压缩前的父指针，核对分量数是否仍可能是 3。
2. 在产线场景只保留 1 条跨簇桥，记录分量数与最大故障域如何从「三簇粘成一块」退回「两块联网＋孤立」。
3. 给别名组加「常用名」字段：并入时若组内尚无常用名则标星，有常用名则显示常用名——对照站内队名归组规则。
4. 阅读 Tarjan & van Leeuwen 1984 关于 linking／compression 组合的表格，列出「union by rank + full compression」对应的均摊界表述。
